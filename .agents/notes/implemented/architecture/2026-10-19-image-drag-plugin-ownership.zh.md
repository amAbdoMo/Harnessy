# Agent Note: 应用布局之外的文件拖放归属

Status: implemented

[English](2026-10-19-image-drag-plugin-ownership.md) | 中文

## 问题

原文件拖放涉及对话图片、Markdown、侧栏预览和输入框投放目标。拖放可能在源组件卸载后继续，失败反馈也可能需要在源面板关闭后保持可见。把这些状态放进布局，会让通用的 owner 依赖图片功能；React provider 还要求独立的图片入口共享祖先。

## 决策

[file-drag 插件](../../../../packages/client/ui-file-drag/README.zh.md) 拥有准备操作、应用内浏览器令牌、保留的原文件、原生桥接选择和本地化失败反馈。入口通过现有注入接口接收显式回调。插件经 `shell.overlay` 展示反馈；布局只声明该通用插槽，不导入图片行为。共享图片原语拥有手势和调用方取消。MIME 命名与传输接受通用文件，图片是当前使用这些能力的展示组件。

Desktop 借用资源前，需要按 Session 范围获得 Host 读取授权，并确认本地文件未变更。Main 为每项准备操作保留确切的窗口与 Host 代次；私有桥接只向 renderer 返回不透明句柄。[Desktop owner](../../../../apps/desktop/README.zh.md) 定义准备上限、临时文件保留期与关闭行为。

## 考虑过的替代方案

**布局或 renderer 中的 React provider。** 拒绝：它把通用应用 owner 与文件传输耦合，并增加入口注册没有声明的祖先要求。

**每张源图片自行持有状态。** 拒绝：源组件移除后，另一入口完成传输前，保留字节与反馈就会退休。应用 owner 让活动拖放独立于源组件继续存在。

**renderer 提供原生路径。** 拒绝：产品文档不能授权 Host 文件系统访问。资源地址必须经过已组合的文件系统与 Session；Main 校验得到的私有路径和内容身份，不把路径暴露给 renderer JavaScript。

## 结果

独立渲染根在一个插件实例内共享传输。托管令牌只能由该实例解析，并且只在输入框范围接受；外部文件投放保留现有接收方式。卸载会取消浏览器读取、清除保留的传输并抑制迟到的原生反馈。Desktop 窗口隐藏到托盘时保留原生 owner；真正退出与确认安装时释放，安装失败后恢复注册。外部浏览器及跨窗口交付不属于已验证的同实例传输保证。
