# Agent Note: 应用自有外观：共享 Select、静默子进程，以及子代理页的第一印象

Status: implemented

[English](2026-09-17-app-chrome-select-startup-and-subagents-polish.md) | 中文

## Problem

对打包后的 Harnessy 桌面应用做了一轮检查，发现多处显得「未完成」而非「有意设计」的地方。

正常启动过程中会出现一个控制台窗口。外壳进程是 GUI 进程，它启动内置的 `node.exe` 时，任何控制台子系统子进程只要没有 `CREATE_NO_WINDOW`，Windows 就会为它分配控制台；重定向 stdout/stderr 并不能阻止这件事。两个真实的 spawn 点——每次启动都会用到的宿主子进程，以及首次运行与升级时的 pnpm 子进程——都缺少 `windowsHide: true`，于是用户看到黑窗一闪（冷启动首次运行最多会出现三次）。

未打包的 Desktop 还可能在渲染器可用前启动失败。它的一次性项目只镜像 pnpm 的虚拟提升目录，因此已退役包留下的悬空链接会中止投影，而新加入的传递 workspace 插件即使已由所属 bundle 声明，也可能缺席。开发启动器还构建默认的官方客户端图，导致 Harnessy 的子代理设置页未进入 Desktop 渲染器。

所有设置里的下拉框都是原生 `<select>`。平台自己绘制它的弹层和箭头，忽略主题 token，与页面其他控件风格不一；Models 页曾用 data-URI 箭头遮盖过这一点，子代理页则没有。

滚动条虽然做过主题化（`ui-theme/styles/scrollbar.css`），但仍像平台原生：8px、直角、滑块紧贴轨道。

子代理页开头就是诊断信息，每个角色还平铺十一条整行覆盖项，用户第一眼看到的是一堵控件墙。

紧凑状态界面也隐藏了有用的区分。侧边栏账户卡片只有在 hover 时才有底色，Subagents 与 MCP 设置项共用回退齿轮图标，运行中 subagent 的目录也没有显示生成各段对话的模型。「新建 subagent」操作与字段提示文字对齐，而不是与输入框对齐。

打包后的 Windows 目录为 735.56 MB，其中包含 48.30 MB 的 Chromium locale 包，尽管 Harnessy 现在只提供英文 UI。发布校准还会先把 249.02 MB 的 pnpm store 解包成一棵完整临时目录，再递归复制进持久 store，之后 pnpm 才能安装 profile。在测量的 Windows 包上，归档验证与解包耗时 34.963 秒，重复的合并复制又耗时 27.121 秒；seed 与核心包完整性验证合计不到一秒。

## Decision

**控制台子进程在源头隐藏。** `apps/desktop/src/host-process.ts` 与 `apps/desktop/src/project-manager.ts` 现在以 `windowsHide: true` 启动子进程，两个测试套件都针对真实的 `spawn` 调用断言该标志（沿用仓库既有的 `vi.mock('node:child_process', …)` 包装模式）。这个标志是唯一有效的手段：`detached` 和 `shell` 本就未设置，stdio 管道与控制台分配无关。

**开发项目沿 workspace 依赖图投影。** 投影先读取 pnpm 的虚拟提升目录，只忽略目标已经不存在的链接，再从 CLI 与 Desktop Host 开始沿每个 workspace 包的包内链接继续遍历。因此，即使 pnpm 没有把某个传递插件的 workspace 链接放进虚拟提升目录，一次性项目仍能解析它。`dev:desktop` 明确构建 `custom-harness` 客户端 profile，使开发渲染器与打包流程使用同一份产品专属客户端图。

**在 `ui-primitives` 中新增共享 `Select`。** 原生 `<select>` 无法主题化，所以应用现在自有一个 listbox：`role="combobox"` 触发器按 `Input` 的几何与 token 绘制（32px、圆角 8、`--dsw-alias-border-l4`、layer-1 填充、品牌色焦点边框），弹层是 portal 出去的 `role="listbox"` 卡片，风格对齐 `Menu`（菜单表面、由 elevation 阴影提供的发丝描边、l2 滚动条重绑定）。它支持分组行、禁用行、跳过禁用项的 Home/End/方向键漫游、Enter/Space/Escape/Tab、外部指针关闭，以及 `aria-activedescendant`（焦点始终留在触发器上）。八个原生 `<select>` 全部移除：Models 页五个、子代理页三个（`DraftSelect` 与模型/推理档位选择器背后各一个）。`packages/client/ui-settings-models/tests/styles.client.spec.ts` 现在断言该包中不会再出现 `<select>`。

**滚动条皮肤变成应用自己的滚动条。** 仍是同一张全局样式表、同一套 token 与间接变量：宽度 10px，滑块为 999px 胶囊形，通过透明边框内缩 2px 并用 `background-clip: padding-box` 保证缩进生效，hover 沿用既有 token，轨道与角落保持透明。`--dsh-scrollbar-width` 同步更新，全圆角半径也像应用中其他胶囊一样带上 `corner-shape: round`。

**交互控件在自身边缘呈现焦点。** 全局 `field-focus.css` 规则覆盖字段、按钮、下拉触发器、开关、标签页、可编辑区域与其他可聚焦控件：获得焦点时把既有边框改为品牌色，并移除外部轮廓与光晕。composer、搜索与重命名表面等由包装器持有的字段通过组件样式改变包装器边框。焦点不会增加边框宽度，因此静止几何保持稳定。

**子代理页先呈现它要编辑的内容。** 顺序为：角色、自动路由、折叠的运行时状态报告、工作区覆盖。展开后的角色卡把“角色详情”与“运行设置”分开，将调用方式从三组带说明的单选项收敛为一个选择器，并把身份、指令、工具、运行时、调度和限制收进“高级”。“测试角色”会刷新相关目录与运行时、验证路由指引，并在不启动子代理、不消耗模型用量的情况下报告所选后端、模型、访问级别与调用方式。每个角色的覆盖编辑器都是折叠的 `<details>`，默认只列出本工作区实际覆盖的字段，直到勾选「显示全部字段」才展开其余部分。

**角色摘要用于比较策略，而不是重复策略。** 每张折叠卡片显示角色用途，以及紧凑的模型、推理强度、访问级别、调用方式和工作区来源 badge。只读访问保持中性，工作区写入使用琥珀色，完全访问使用红色。启用状态采用开关，旁边的标签只显示当前的“已启用”或“已禁用”状态；由 Agent 选择的路由使用明确标签“Agent 可选择”；工作区卡片显示“自定义”或“继承”。路由指引默认折叠，直到进入编辑；“测试角色”执行既有的不消耗用量解析检查。创建与复制会打开禁用的本地草稿，每个展开编辑器都会暂存全部字段直到点击“保存更改”，取消不会写入。Client 验证会在一次完整写入前解释 Host 中可由用户修正的必填字段；新角色派生的 id 在首次保存前仍可编辑。页面会在已启用的自动角色明显重叠时警告，“委派限制”以共享控件编辑并发数与默认超时，而“新建 subagent”操作使用与输入框一致的 32px 高度。

**MCP 导入兼容提供方格式，但忠实保留 transport 语义。** 导入器接受常见的 `mcp`、`mcpServers` 与 `servers` 根节点或直接映射，再把本地 argv、命令加参数记录与远程 HTTP 记录标准化后交给既有受保护 Host 保存操作。脱敏预览只公开名称、派生出的唯一命名空间、transport、启用状态与受保护值数量，不渲染环境变量值、header、URL、命令或参数。不受支持的 SSE transport、逐服务器 timeout、额外 header、格式错误条目与容量限制会作为可见警告或跳过记录保留。已接受的 profile 顺序保存，因此 Host 拒绝时有确切停止位置。

**产品专属设置移除重复入口。** 在 MCP 页面，全局设置文档操作会让位于只打开 `$DSH_HOME/mcp-servers.json` 的 MCP 专属操作；Host 会在下一次状态读取时验证文件修改，并让界面写入与其同步。直接编辑要求值可读，因此这份仅供本机所有者使用的文件可能包含 MCP 凭据，并不是可共享导出。连接状态会改变整张卡片的边框颜色，而不再绘制独立左侧轨道。Harnessy 的 Plugins 页面省略旧的 Subagent 模型选择卡片，Models 页面省略内置 `deepseek-official` 行与引导步骤，同时保留自定义提供方路由。角色编辑会提交一个完整且已验证的定义，而不是一串局部写入。

**溢出是布局缺陷，不是审美取舍。** 覆盖行声明了四条网格轨道却只有三个子元素，控件因此落入 `max-content` 轨道，其固有宽度把整行撑得比模态框还宽。现在该行是两列网格（控件，然后是状态徽标与重置按钮），在 640px 以下改为堆叠；字段网格用 `minmax(min(200px, 100%), 1fr)` 收窄；角色卡的操作行允许换行；设置滚动区补上 `min-width: 0` 与 `overflow-x: hidden`，使任何区块都无法再把面板撑宽。子代理页的输入框与多行文本框改用与共享控件一致的几何与 token，让同一表单行看起来出自同一家族。

**紧凑状态界面公开稳定身份。** 侧边栏账户卡片静止时使用交互 hover 填充，hover 或打开时使用侧边栏 active 填充。设置页把 Subagents 映射到分支图标，把 MCP Servers 映射到数据库图标，不再使用回退齿轮。subagent 目录行的次要信息首先显示来自持久化模型选择投影的确切模型 id：优先采用最新已消耗的选择，在首次请求前则回退到下一次选择。「新建 subagent」按钮与输入框对齐，提示文字仍保留在字段下方。

**通知跟随需要关注的工作。** 现有浏览器本地账户切换历史现在还会记录运行中的 Session 变为空闲，以及新的批准、问题或计划审核交互。首次观察到的 Session 与交互 snapshot 会建立静默基线，因此刷新不会再次报告已有状态。后续转换会添加一条未读记录和一个临时 toast；Desktop preload 同时公开一个长度受限且只用于通知的 IPC 操作。打包后的 Windows 应用启动时会创建或修复开始菜单快捷方式，使 executable 绑定到 Electron 在 ready 前设置的同一个 application id。主进程会校验每个通知的标题与正文，并保留其 Electron 对象，直到 Windows 关闭、拒绝或激活通知；用户选择通知时，应用会获得焦点。铃铛 badge 显示未读数量，不再只显示存在提示点。

**发布校准只写入一次包字节。** 运行时验证现在只把 pnpm 的小型版本化 SQLite 索引解包到事务 scratch，同时检查每个归档条目的分片分配、类型、重复项和声明数量。只有所有分片都通过后，第二次归档遍历才把非索引包文件直接流式写入持久 Desktop store。两次遍历都由四个有界 worker 处理彼此独立的分片；在同一磁盘上使用全部 16 条通道反而更慢。随后 staging 索引以事务方式合并，seed 记录优先，插件专属记录继续保留。归档验证失败不会修改持久 store；后续写入失败至多留下经过验证的内容寻址包字节，旧索引在最终合并前仍是权威。测得归档到 store 阶段从 62.085 秒降至 18.283 秒（70.6%），不包含后端健康启动的完整首次安装耗时 48.676 秒，匹配发布的热校准耗时 9.21 毫秒。这些是最新的本地 Windows 诊断数据，不是跨机器 CI 预算。

**只提供英文的产品只携带一个 Chromium locale。** Electron-builder 仅保留 `en-US`；许可证、GPU fallback、Node.js、pnpm 与离线 seed 均不删除。测量的未打包 Windows 产物从 735.56 MB 降至 687.82 MB，locale 目录从 48.30 MB 降至 0.56 MB，同时保持运行时与恢复设计不变。

## Alternatives considered

**保留原生 `<select>` 并加大改造力度。** 不新增任何 API，且 Models 页已经在这条路上走过一段。它输在原生 `<select>` 的弹层属于操作系统：颜色、行高、勾选标记与滚动条都不在页面掌控之内，因此它永远无法与应用的 listbox 一致，而 data-URI 箭头本身就是触到上限的证据。

**把 `Menu` 扩展成 select。** 少一个原语，且 `Menu` 已经具备 portal、定位与关闭。它输在语义：`Menu` 是 `role="menu"`/`menuitem`，没有漫游焦点或 `aria-activedescendant`，基于它的下拉框会把自己播报成菜单，而屏幕阅读器对下拉框期待的是 listbox 契约。

**只修源码不加测试。** 这个标志只有一个词，而且「显然」正确。它输在没有任何东西约束它：如果没有断言，下一个 spawn 点——或这两处的重构——都会静默地把窗口带回来，而只有在 Windows 上运行打包应用才能看到。

**按界面分别美化滚动条。** 每个面板各自声明自己的滚动条。它输在应用已经有重绑定契约（在浮层面板上重绑 `--dsh-scrollbar-thumb{,-hover}`），而用户看到的问题在于滚动条的**形状**，那是所有界面都应共享的。

**把整个「工作区覆盖」区块折叠起来。** 这是让页面平静下来的最短路径。它输在该区块承载着工作区特性唯一的入口：用户找不到的控件不是更简单，而是消失。按角色折叠既能通过摘要行保留计数，又让字段只隔一次点击。

**在 subagent 目录中解析友好模型名。** 友好标签可以比确切 id 更精致。它输在对话页头拥有持久化会话投影，却不拥有提供方目录；加入该依赖会让真实状态取决于第二个异步数据源。即使提供方离线或被移除，确切模型 id 仍然可用。

**安装后压缩或删除离线 seed。** 这会比 locale 精简更明显地降低未打包应用的文件系统占用。它输在 seed 是签名的离线恢复与升级输入，而逐分片压缩会用解压耗时和更不稳定的差分区间换取安装体积。产品保留这项恢复能力，只删除无法使用的文件。

## Consequences

打包应用启动时不再出现控制台窗口，两个 spawn 点都有测试为证。下拉框在所有出现的地方外观与行为一致，将来若在 Models 包中重新引入原生 `<select>`，它不会触发 lint，但会被测试发现。

未打包应用能跨 workspace 包的新增与移除正常启动，不再要求开发者手工修复陈旧的虚拟提升链接。常规构建包含子代理页以及产品专属的模型与推理档位控件。

子代理页打开时先显示紧凑的角色摘要，展示有意义的差异而不重复标签。用途与策略 badge 让用户一眼比较访问风险、路由选择与工作区自定义；路由指引与可选控件在编辑前保持安静。运行时诊断保持为一行折叠摘要，只有在“测试角色”结果需要排查时才展开；工作区编辑器的默认视图仍是「本工作区改动了什么」。共享限制不再要求直接编辑配置文件，重叠的自动角色也会在竞争同一请求前变得可见。

常见提供方配置文件中的 MCP profile 可以一起预览和导入，无需逐字段复制凭据。预览可安全展示，不受支持的 transport 细节保持明确。专用 MCP 文档提供一个不打开无关设置的直接编辑来源；它属于本机敏感数据，而不是脱敏导出。

账户页脚现在像一个常驻启动入口，而不是透明的点击区域。设置导航可一眼区分 agent 与服务器，创建操作与其提交的值排成一线，subagent 目录也能在无需额外网络读取的前提下标明活跃与已完成对话所用的模型。

首次安装与发布校准不再创建并递归复制第二份完整 pnpm store。异步归档工作期间加载页仍保持响应，验证仍会在持久 store 变化前完成，插件索引条目也能在优化路径中保留。只要发布版本、包版本与 seed 完整性描述文件匹配，热启动仍会跳过全部 seed 归档工作。

Windows 包不再携带应用无法选择的 Chromium 翻译。剩余的大体积来源都是有意保留：Electron 及其渲染 fallback、上游 Node.js 与 pnpm 运行时，以及能重建可写 Desktop profile 的离线 seed。

`ui-primitives` 增加一个自带样式表的控件，以及一份 16 个用例、保持 100% 覆盖率的测试；README 目录列出了它，Models 与子代理包不再自带下拉框样式。两个设置页的测试现在驱动共享控件（打开弹层、选中某行），而不再读取 `HTMLSelectElement.value`。

有两处限制是有意保留的。`Select` 没有首字母跳转：方向键与 Home/End 漫游已覆盖应用当前渲染的列表，若需要，可在不改变 API 的前提下补上。设置滚动区会横向裁剪（`overflow-x: hidden`），因此将来真正需要宽表格的区块必须自带横向滚动，而不能依赖面板。
