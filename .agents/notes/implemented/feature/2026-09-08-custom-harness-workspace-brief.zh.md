# Agent Note: Custom Harness Workspace Brief as a bounded human command

Status: implemented

[English](2026-09-08-custom-harness-workspace-brief.md) | 中文

## 问题

Custom Harness 需要一个有用的端到端产品操作来展示其扩展架构，同时不授予新的模型能力，也不创建另一个持久化权威。工作区摘要可能暴露仓库名称、路径、状态和 manifest 内容，因此不受约束的实现可能逃离所选工作区、读取过多数据、跟随符号链接，或在重连后重复副作用。仅浏览器摘要还会绕过宿主文件系统与沙箱策略，而生成文件会增加产品并不需要的写入与清理行为。

## 决策

Workspace Brief 是带有独立宿主和浏览器插件的人类命令，仅由 Custom Harness 产品 bundle 启用。

- `dsh-workspace-brief` 注册 `/workspace-brief [--git]`。它不接受路径，通过 `ctx.workspaceRegistry` 解析准确的会话 cwd，并在生成结果前拒绝缺失、未注册、不可用或非 Git 工作区。
- runner 通过 `ctx.fs` 观察顶层清单和常规、非链接的 `package.json`。它通过 `ctx.shell` 使用当前只读沙箱策略运行一条常量 Git 命令。耗时、manifest 字节、Git 字节、清单行、状态行、字段长度和最终 Markdown 长度均有独立上限。
- Manifest 失败是不完整结果，因为仓库身份和 Git 事实仍然有效；工作区、权限、Git、取消和超时失败会分别结算。显式重试只重复读取操作，并创建另一个普通命令生命周期。
- `dsh-client-ui-workspace-brief` 贡献一个已打开会话的标题操作和一个带键命令卡片。该操作防止并发重复分派，而卡片折叠 `command/run` 与 `command/done`，因此重新加载和重连会显示已记录输出，而不会重新运行检查。
- 命令事件仅用于日志，绝不进入模型历史。此功能不添加数据库、文件、网络请求、模型工具或模型调用。

## 考虑过的替代方案

- **在浏览器中运行检查**——已拒绝，因为浏览器没有权威的工作区、文件系统或沙箱能力，并且会复制宿主策略。
- **把 `WORKSPACE-BRIEF.md` 写入仓库**——已拒绝，因为简报是展示状态；文件会修改用户内容，需要覆盖策略，并产生清理与重试语义。
- **暴露模型工具**——已拒绝，因为 Phase 5 授权的是人类产品操作，而不是新的模型能力。工具需要独立的能力、prompt、权限和模型体验审查。
- **创建 Workspace Brief 数据库**——已拒绝，因为命令生命周期已经提供持久的逐会话重放与配对；另一个存储会引入同步与删除所有权。
- **接受任意路径或递归发现**——已拒绝，因为会话的已注册工作区就是产品边界，而有界顶层事实足以形成简报。

## 后果

该功能贯穿真实产品 UI、Remote 命令分派、宿主策略、文件系统与 shell 能力，以及持久会话展示，同时仍可作为两个插件行移除。用户会得到稳定的时间点摘要和明确的不完整数据标签；重试无法改变工作区内容。固定上限会省略深层项目结构、完整 diff 与大型状态集，标题操作也会有意生成默认的不含状态形式。聚焦测试固定成功、验证、失败分类、取消、重放、幂等性与插件禁用/重新启用行为。
