# Agent Note: 限定范围的网站控制交接

Status: implemented

[English](2026-09-27-scoped-website-handoff.md) | 中文

## Problem

网站管理同时涉及已认证的浏览器、MCP 连接和重复的 Agent 操作。将模型提供商账户用于网站登录会混淆互不相关的凭据。持久浏览器登录本身无法区分人工操作与 Agent 权限，而取消请求也不能确认上游修改或原生操作已停止。

## Decision

桌面网站配置档案记住站点、账户标签及 MCP 配对，并使用持久 Electron 分区隔离浏览器认证。网站 Cookie 与[模型凭据记录](../architecture/2026-08-13-credential-records-and-authorization-flows.zh.md)保持分离。[可选工作区决策](2026-09-12-optional-workspace-sessions.zh.md)继续负责工作目录，而不负责网站授权。

人工登录和接管禁止 Agent 观察页面，包括页面标题和截图。准备操作识别发起请求的 Session 及精确的访客页面，但不授予访问权限。显式恢复仅授权一个活动请求，每次调用仍需新的限定范围同意。记住的登录和显示的账户占用状态均不代表页面权限，防止重新打开的配置档案或别名静默继承授权。

支持的工作优先使用 MCP。浏览器后备操作单独获取同意，因为 MCP 权限不授权另一种操作机制。原生进程和 Host 检查将权限绑定到精确的 Session、所属窗口、访客页面、配置档案、MCP 绑定及当前请求修订。接管立即撤销新操作的准入，而账户占用持续到已发出的上游调用和原生工作实际结束。排空失败保留占用，而不是让同一账户承受重叠操作。

[桌面 README](../../../../apps/desktop/README.zh.md) 和[侧栏浏览器 README](../../../../packages/client/ui-sidebar-browser/README.zh.md)负责操作限制及平台行为。Web 模式不声称提供桌面端的持久原生浏览器或登录隔离。

## Alternatives considered

**使用模型提供商登录作为网站账户。** 拒绝，因为提供商授权既不能认证网站，也不能隔离多个网站账户。

**随浏览器登录记住 Agent 授权。** 拒绝，因为持久认证会在没有新同意的情况下静默授权未来的 Session、页面和调用。

**请求取消时就释放账户。** 拒绝，因为取消调用方后，已发出的 MCP 修改或原生操作仍可能运行。是否可以重新使用账户由实际结束状态决定，包括无法确认的清理。

**恢复后允许任意页面 JavaScript。** 拒绝，因为脚本和工作线程可能在接管后继续运行；重新加载不能保证其终止。

## Consequences

登录按网站 Cookie 的到期规则保留，但未来工作不会因此自动受信任。精确请求同意和排空失败后的保留占用增加了人工交互，也可能在清理成功前阻止账户复用。限制浏览器操作放弃任意自动化，换取有界且可撤销的准入。记录的 Session 检查点保留同意及工具结果，不记录人工登录秘密；测试使用受控适配器，真实 Electron 登录和在线提供商验收则属于独立证据。
