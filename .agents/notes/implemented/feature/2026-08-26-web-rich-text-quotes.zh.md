# Agent Note: Web 输入框中的持久富文本引用

Status: implemented

[English](2026-08-26-web-rich-text-quotes.md) | 中文

## 问题

选中的摘录需要支持原子编辑和重新加载后的草稿恢复，而不依赖来源消息持续可用。持久化派生文本节点或来源索引会为权威消息文本引入相互竞争的所有者。

## 决策

现有输入框在引用标记旁拥有原子 QuoteNode 编辑和语义 DraftSnapshot 范围。剪贴板文本使用规范 Markdown；编辑器检测将每条摘录视为一个字符。运行时标识、回调和本地化标签不进入浏览器存储。提交失败时恢复同一语义文档。

消息包含普通 Markdown 文本。message-quotes 插件通过 Conversation 拥有的纯 JSON 文本匹配器识别显式块引用行。插件按字面渲染解码后的摘录，不应用嵌套引用装饰。提交文本仍接受 Session 引用和技能处理。Harnessy 的普通文本呈现通过工厂的可选渲染器保留现有文件和技能导航；该回调属于呈现状态，不是匹配事实或存储节点。

Chat 拥有可见选择提取、局部操作定位、裁剪、输入框遮挡和关闭行为。插件拥有手势准入与引用操作。已完成的持久 Assistant 文本、展开的思考和用户气泡可提供摘录；流式、中断及无标识的 Assistant 输出不可提供。插入会重新检查实时 Session 和输入框可编辑状态。插入失败时保留选择。右键菜单取消仍在原始事件中同步发生。

## 考虑过的替代方案

**持久化编辑器 JSON 或派生 UserText 节点。** 编辑器标识和显示规则独立于权威文本演变。现有语义草稿表示拥有恢复行为。

**保留来源导航或消息专用引用索引。** 导航需要持久坐标、可用性检查和失败处理。引用索引重复显式 Markdown，并使手写和插入的块引用行为不一致。提交后只保留选中的文本。

**替换 Harnessy 的引用呈现。** 现有导航所有者已处理文件路径和技能预览。保留该所有者可避免竞争渲染器并保持自定义行为。

## 验证

输入框测试覆盖原子删除、撤销、存储恢复、Markdown 提交及发送失败恢复。匹配器和渲染测试覆盖字面嵌套引用、来源范围与现有导航。Chat 测试区分持久消息与流式、中断内容；行内 Slot 测试覆盖条目缺失和失败。

## 影响

未发送的摘录保留在浏览器本地草稿存储中。识别仅覆盖显式引用行，不处理 Markdown 懒续行或围栏代码解析。来源导航需要单独的持久坐标设计。派生 JSON 节点与呈现回调不会替代 Session 内容。
