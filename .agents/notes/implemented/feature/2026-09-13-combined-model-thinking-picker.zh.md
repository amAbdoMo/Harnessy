# Agent Note：模型与推理强度组合选择器

状态：已实现

[English](2026-09-13-combined-model-thinking-picker.md) | 中文

## 问题

composer 原先把模型与推理强度拆分在嵌套菜单中。狭小界面不便比较不同提供方的模型，同时更改两个值需要重复打开控件，并且界面无法区分组合更改与只更改其中一项的意图。

## 决策

composer 模型位会打开一个居中的可搜索对话框，左侧按提供方分组显示模型，右侧显示暂存模型所公布的推理强度。单击模型会暂存它；接着单击推理强度会提交完整组合，并在宿主接受后关闭。双击模型只提交模型：若目标模型支持当前强度则保留，否则回退到目标默认值。双击推理强度则针对持久化的当前模型提交该强度。

单击推理强度的操作会等待 230 毫秒，使浏览器双击能够取消待提交的组合。通过可见关闭按钮、Escape 或遮罩关闭时会丢弃草稿。选择被拒绝时对话框保持打开，并使用现有 toast 表面。对话框从共享常驻目录立即渲染，在本地筛选，只有目录处于 idle 或失败状态时才重新加载。

桌面窗口现在会在打包运行时协调之前出现，并在该工作完成期间显示现有的品牌启动页。热启动会先比较活动配置与打包的完整性清单；当种子不会被使用时，会跳过昂贵的逐文件种子验证。安装与升级在打包内容进入可写状态之前仍会执行完整验证。

Windows 安装程序保持 `com.amabdmo.customharness`、`Harnessy.exe` 与 `Harnessy` 快捷方式名称稳定。禁止更改安装目录，使升级复用已登记的位置，electron-builder 会保留快捷方式，而不会删除并重建任务栏固定项背后的目标。

## 考虑过的替代方案

- **保留嵌套菜单**——拒绝，因为它隐藏模型与强度的上下文，并要求连续重复打开。
- **增加 Apply 按钮**——拒绝，因为要求的“模型后选择强度”手势已经构成完整选择。
- **单击强度后立即提交**——拒绝，因为浏览器会在 `dblclick` 前先发出 click 事件；没有短暂等待就无法可靠实现只更改强度的双击。
- **继续允许选择安装目录**——拒绝，因为 electron-builder 对可能移动应用的手动安装程序会有意停用快捷方式保留。

## 后果

选择器不会增加启动请求或依赖。冷升级期间用户会立即看到可响应的 Harnessy 窗口，而配置匹配的普通启动会避开种子扫描。普通组合更改在关闭前会有一段很短且有意的双击识别等待。没有推理元数据的模型会在单击模型时完成选择。从旧安装程序升级时，如果可执行文件路径或快捷方式已经被替换，用户可能需要重新固定 Harnessy 一次；之后同一身份的升级会保留该固定项，而全新安装会使用正常的 Windows 当前用户应用目录。
