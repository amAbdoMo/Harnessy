# Agent Note: 原生 Android 中继权限

Status: implemented

[English](2026-10-12-native-android-relay-authority.md) | 中文

## 问题

手机需要在离家后访问已有 PC 会话，而不安装私有网络客户端或管理第二个工具型服务器。浏览器操作者凭据授予的权限远超过查看会话和排队追加文本任务。网络可达性与持有邀请均不代表 PC 所有者已经同意。

## 决策

原生 companion 使用 PC 主动出站连接与独立密文中继。中继路由经过认证的套接字身份，但不授予会话权限，也不接收会话明文。PC 拥有的授权与私有 Desktop 所有权能力执行封闭的读取／任务操作集合。Agent 和持久化仍属于现有 PC 进程。

配对使用限时邀请，由 Main 明确批准手机完整指纹。renderer 仅接收可用性、连接状态和配对数量；批准标识符和邀请秘密都不经过它。兼容 AndroidKeyStore 的 P-256 身份与域分离签名转录绑定固定 PC 密钥、中继来源及临时 ECDH 交换。双方加密确认完成后才能使用应用操作。

追加任务保留现有会话的工具权限，不增加远程工具批准权限。最终准入检查在 inbox 插入前立即同步执行。确认仅代表易失 inbox 准入，因此断连不能成为自动重试的依据。Android 只持久化不确定性标识符和配对修复标记，不保存任务文本或离线修改队列。

凭据源故障永久撤回该提供方实例的 companion 权限，因为最后有效的缓存读取不能证明当前授权。撤权持久化失败也会禁用当前 companion 实例，而不是虚构持久撤权。内核排他锁防止暂停的所有者失去同一 home 的身份锁，但不保护复制后的凭据 home。

## 考虑过的替代方案

**把私有浏览器访问作为原生传输。** VPN 设置与完整操作者权限不满足安装后一次配对、窄权限访问的要求。独立的[私有浏览器决策](2026-10-11-harnessy-android-companion.zh.md)仍适用于该可选兼容功能。

**启动另一个 PC Web 进程或公开操作者 Gateway。** 另一个进程不拥有正在运行的 Agent，还可能争用持久数据。公开宽权限 Gateway 也会使 UI 筛选成为无效的授权机制。

**确认丢失后重试或持久化离线任务队列。** 准入可能先成功，随后回执或检查点丢失。自动重放可能重复任务；明确检查并由用户重新决定才能诚实保留不确定性。

## 后果

PC 必须保持唤醒和联网。托管 TLS／代理、Android 配置／签名及设备互操作仍是部署责任；源码审查与 TypeScript 检查不能证明运行安全。[原生设置与验收指南](../../../../HARNESSY-ANDROID-COMPANION.md)拥有这些操作。

中继观察路由身份、大小及时间。剪贴板同步可能泄露邀请；Android、PC 及其发布者仍是受信任端点。移除授权阻止未来授权与准入，但不删除已送达数据，也不取消 PC 已准入的任务。

私有浏览器记录只在主要 Android 工作流方面被部分取代。其浏览器认证、私有代理依据与更宽操作者语义仍适用，因此保持活跃并互相链接，而不重写或归档。
