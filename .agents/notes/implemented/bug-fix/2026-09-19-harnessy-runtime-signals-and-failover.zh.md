# Agent Note: 保持 Harnessy 运行信号可执行

Status: implemented

[English](2026-09-19-harnessy-runtime-signals-and-failover.md) | 中文

## 问题

Harnessy 暴露了多项运行控制，但在真正需要它们时并未始终可靠地保持其意图。Session 可以通过旧委派工具绕过已配置的子代理角色，把重复工作拆成每个项目一个子代理，并让每个子代理完成都变成桌面通知。根 Session 完成通知根据 running 标志消失来推断，因此可能反复显示含糊的“已停止运行”，而不是报告已记录的终止结果。长时间运行也难以浏览：每次工具调用都占据完整 transcript 行，已应用文件变更没有逐 Turn 摘要，运行超过一小时后经过时间仍只显示分钟。即使持久 Session 中已经存在 MCP 调用，页头仍可能保留过期的活动投影。Codex 账户切换会等到显示的窗口达到 100%，因此某次请求可能在下一次主动检查之前耗尽余量并停止。用量填充还会在普通刷新时从零重新播放，使稳定的额度看起来不一致。

## 决策

`custom-harness` profile 只把角色目录的 `list_subagents` 与 `delegate` 工具作为创建子代理的路径。该 profile 禁用通用的进程内委派工具，并继续挂载 Command Code 后端，但关闭其角色目录出现之前的通道工具。角色目录工具指引要求首次委派前读取目录、选择最匹配的配置角色、把相关工作合并为一个完整批次而不是为每张图片、每个文件或每条记录各建一个子代理，并由父 Agent 负责最终整合与验证。自适应并发让父 Agent 选择最小的有效独立批次，同时共享运行闸门保留 16 的硬上限；手动设置可施加更严格的上限。

子 Session 完成状态仍显示在子代理活动界面中，但不会生成通知中心或桌面完成消息。页头报告“工作中”与“已完成”总数，已完成的直接 child 默认折叠，并且每行报告有效模型与推理强度。需要人工决定的子代理请求仍可通知。铃铛用一个不带数字的圆点表达未读状态，同时其无障碍名称保留精确数量。根 Session 通知等待 `turnOutline` 投影的终止分类，并区分完成、停止与失败。同一次运行存在待批准、问题或计划审核时，会抑制其终止事件。成功完成仅在 Harnessy 位于后台时请求原生通知；停止、失败和需要操作的事件会立即保持可见。

Compact Chat 会把 Assistant 进度消息之间连续的实时推理行与工具行分组，同时让被 disclosure 隐藏的行 renderer 保持挂载；失败调用会强制展开该组。成功工具结果只有在包含通过校验的已应用 diff 元数据时才贡献 Turn 文件总计，选择文件会在右侧栏打开已记录的 hunk。没有 diff 元数据的 shell 输出绝不会被推断为编辑。经过时间依次使用秒、分钟与秒，以及小时加剩余分钟和秒。

Session 页头的 MCP 操作会在每次渲染时从最新投影派生调用活动，不再按稳定的外层 chat 对象缓存。空闲时仍显示标签，运行时显示调用数，并使用较暖的语义成功色与错误色。服务器连接健康继续来自 MCP manager；逐 Session 调用继续来自持久工具事件。

Codex 自动切换把任一标准窗口 95% 的用量作为主动阈值，并且只选择所有标准窗口仍低于该阈值的已刷新替代账户。provider 确认额度错误后，Host 会再次刷新用量，并且仅在该刷新确实提交了不同的活动凭据时重试当前轮次。用量条直接显示最新测量百分比，不再在刷新后重新播放填充动画。

工作区角色覆盖继续受支持，因为它是让单个项目比全局角色目录更严格的最窄方式。其编辑器默认折叠，并会报告工作区是继承全局角色还是包含自定义字段。

## 已考虑的替代方案

**使用固定并发默认值。** 一个通用数字无法区分独立研究与共享文件或可变 MCP 工作。自适应模式把批次大小交给父 Agent，手动上限支持更严格的项目，而 16 始终是安全上限而非质量目标。

**保留所有委派表面并依赖提示词。** 模型可以选择任何已注册工具，因此文字无法保证使用配置角色。从 Harnessy 组合中移除竞争性的创建工具，可在工具边界表达角色策略，同时保留 Command Code 后端且不影响其他 profile。

**为每个子代理完成都通知。** 完成消息在子代理面板中有用，但当父 Agent 已经拥有整个任务时，它们会成为重复的桌面噪音。需要人工操作的请求仍然通知，因为沉默可能使工作停滞。

**把每个成功命令都视为文件变更。** 命令文本与退出状态无法证明修改了哪些文件或应用了什么内容。把摘要限制在已记录的 diff 元数据上，会得到更小但可信的总计，并确保侧栏预览可以从 Session 数据重现。

**只在 100% 时切换。** 用量报告与请求消耗不是原子操作。95% 的主动阈值提供余量，而额度错误恢复路径覆盖两次检查之间仍触及 provider 上限的请求。

**移除工作区覆盖。** 移除它可以简化页面，但会迫使用户仅为收紧一个项目的模型、访问级别或指令而复制全局角色。折叠编辑器能保留有用作用域，同时不让它占据日常设置流程。

## 后果

Harnessy 会一致地使用配置角色创建新子代理，批处理指引减少 token 浪费与冲突写入，但不会阻止有意的并行工作。自适应模式让父 Agent 在 16 个运行的上限下保留最终判断，手动模式则可降低该上限。紧凑活动界面把实时工作与已完成历史分开而不隐藏后者，可信的 Turn 总计则让代码进度无需逐行阅读每个工具调用即可检查。通知历史聚焦已记录的根 Session 结果与可执行请求，同时成功的前台完成不会制造重复原生噪音。Session 中已经存在的 MCP 调用无需改变 transport 即可显示。Codex 可以在耗尽前切换，并在存在另一个符合条件的已保存账户时，从确认的额度失败中恢复当前轮次。代价是文件总计会有意省略没有有效 diff 元数据的修改，Harnessy 不再暴露更广泛框架 profile 中可用的通用与旧角色目录委派工具，并且在 95% 时切换可能会在旧账户中留下少量未使用容量。
