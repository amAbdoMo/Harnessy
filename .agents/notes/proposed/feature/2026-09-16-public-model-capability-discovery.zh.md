# Agent Note: Public model capability discovery, reasoning efforts first

Status: proposed

[English](2026-09-16-public-model-capability-discovery.md) | 中文

## 问题

在 Harnessy 中新增提供方，至今仍意味着逐模型声明推理等级。承载这件事的 seam 早已存在且可用——`LlmRuntime.registerModelCapabilitySource` 供给 `LlmDiscoveredModel.reasoningEfforts`，运行时统一归一化，Models UI、组合器与子代理预检都读取其结果——但只有一个来源在供给它：读取该 CLI 本地目录的 Command Code 集成。其它网关的模型因此始终处于未声明状态，即便端点接受推理参数，组合器也不会给出等级控件。

可靠的公开元数据确实存在。2026-09-16 对线上端点的核验结果：`models.dev/api.json` 列出 217 个提供方，其中 160 个以 `reasoning_options: [{ type: 'effort', values: [...] }]` 形式发布了等级列表；OpenRouter 的 `/api/v1/models` 列出 444 个模型，其中 170 个发布了 `reasoning: { supported_efforts: [...], default_effort }`。两者都无需密钥且可机器读取。

仅按模型 id 匹配并不安全，同一次探测就说明了原因。一条配置路由列出 `gpt-5.6-sol`，经某个提供方条目解析为 `low, medium, high`，而 `gpt-5.6-luna` 经另一个条目解析为 `none, low, medium, high, xhigh, max`；`claude-sonnet-4-6` 在不同条目间同样不同。模型 id 并不标识网关，而决定存在哪些推理控件的正是网关。

## 提案

一个解析层，供所有界面消费，并遵循固定优先级。

**优先级。** 1. 适配器／提供方原生模型元数据。2. 本地提供方专用集成，含 Command Code。3. 实时且带缓存的公开元数据，按提供方匹配。4. 随包发布的公开快照，采用同样的匹配。5. 未声明。较低层级永不覆盖较高层级，因此既有声明与本地集成的答案都优先于任何公开数据。

**一个新 Host 包**承载该层：统一接口之后的各个来源、优先级遍历、匹配、缓存与随包快照。`registerModelCapabilitySource` 仍是接入 LLM seam 的唯一接线，因此运行时依旧是唯一的归一化者，任何消费方都不需要知道数据库的存在。

**按提供方匹配。** 对 models.dev，路由配置的 `baseURL` 会被归一化为主机名——转小写、去掉默认端口、去掉末尾斜杠、去掉末尾的 `/v1` 或 `/v1/` 段，使拼写上的细微差异无法破坏比较——再与每个提供方条目的 API 主机名比对；随后只在该提供方内部匹配模型 id。对 OpenRouter，仅当路由确实指向 OpenRouter 时该来源才作答，判断依据是主机名或路由 id，绝不因为某个模型 id 出现在其目录中就作答。索引按每份元数据世代构建一次，且每次查询都同步作用于已加载的快照，因此模型发现永远不需要引入网络依赖。

**仅按模型 id 的匹配只是建议，永远不是能力。** 它们会带着来源信息出现在同步工具与诊断中，必须在显式接受之后才会被持久化。它们本身永远不会抵达组合器或子代理。

**来源信息随答案一同传递。** 推理字段会获得一个伴随描述，说明其出处：来源名称、匹配方式（`provider-host`、`provider-id`、`model-id`）、命中的提供方条目、数据是实时、缓存、随包还是本地，以及抓取时间。该类型带有一个能力判别字段，使后续能力——工具支持、视觉、结构化输出、上下文上限、模态、温度——可以沿用同一形状而无需改动机制；本次不实现其中任何一项。

**快照与实时刷新并存。** 包内随附一份快照，带有 schema 版本、生成日期，以及构建它所依据的每份捕获的身份，因此可回答其陈旧程度。实时刷新是可选的，并带 TTL 缓存在磁盘上；刷新失败会保留先前数据并继续供给，而随包快照是底线。因此网络故障永远不会移除已经可用的控件。畸形或不完整的响应会被整份丢弃，且单个来源失败绝不影响其它来源。

**配置。** 一个全局配置段，可选的逐 profile 覆盖，形状为 `modelCapabilities.publicMetadata: { enabled, refresh: auto|manual|never, cacheTtl }`。只有在启用时才会发生网络访问，因此 `enabled: false` 或 `refresh: never` 让部署完全可用且完全离线，由快照与本地来源供给。启动永不因刷新而阻塞；首次读取使用现有内容，刷新在后台落地。实现时该段落落在 `model-capabilities` 这一设置命名空间之下，因为设置接缝的顶层键必须是小写连字符标识符。

**命令行。** 该解析层同时也是一个命令界面：一个同步命令，具备只读检查模式与写入模式；以及一个 explain 命令，打印完整链路——按顺序列出每个来源、是否命中、为何跳过、最终集合，以及任何有歧义或被拒绝的仅 id 匹配。写入模式只持久化按提供方匹配的结果，绝不覆盖用户或本地集成提供的声明，并通过设置文档自身的 API 编辑它，以免无关格式发生变动。

**冲突。** 当两个数据库都对某条路由带有按提供方的数据时，与所配置路由相对应的来源直接胜出；各自主张绝不合并为并集，因为并集将给出两个来源都未针对该网关声明过的等级。

## 考虑过的替代方案

**把仅按模型 id 的匹配当作权威。** 放弃，依据即上文探测结果：同一个 id 经不同提供方解析出不同等级集合，把某个网关的主张用在其它的模型上，会给出端点在中途就会拒绝的等级。

**只用冻结快照，或只用实时抓取。** 放弃：只有快照会静默变旧，只有实时抓取则让该功能依赖网络，并在网络不可用时移除控件。两者并存、以快照为底线，才能在任一条件下都成立。

**把两个数据库合并成一个答案。** 放弃：并集会静默造出任何提供方都未声明过的等级集合，来源也无从归属。

**在 Models UI 或组合器内部完成解析。** 放弃：同步工具、诊断、选择器、组合器与子代理预检必须一致，一个共享解析层能做到这一点，并行实现做不到。

**在解析阶段为未声明模型自动宣称等级。** 放弃：仅凭 id 的推断会在没有给用户任何复核机会的情况下变成请求参数，而这正是声明模型存在的意义所要防止的失败。

## 验收标准

切片 1 已在 `packages/llm/model-capabilities` 中实现：解析层、来源类型、来源接口、两个数据库的按提供方匹配、仅按模型 id 的建议检测，以及夹具驱动的测试。它通过 `LlmRuntime.registerModelCapabilitySource` 注册，目前还没有网络、缓存、配置或命令界面，因此下列标准仅在已存在的组件范围内成立。

切片 2 加入了随包快照：`src/snapshot/public-model-capabilities.ts` 由 `pnpm run gen-model-capability-snapshot` 从已提交的精选捕获生成，经 `loadBundledPublicCatalogs()` 以 `origin: 'bundled'` 载入，并由 `pnpm run verify-model-capability-snapshot`（属于 `doc-sync`）校验其新鲜度。它按切片 1 解析器已经在读取的文档形态承载每个目录，因此不存在第二个匹配器。该产物显式声明其 schema 版本、生成时间，以及每份捕获的输入路径、内容摘要与条目数；`--check` 复用已提交的时间戳，因此门禁只会因内容失败，绝不会因墙上时钟失败。

切片 3 加入了实时层：`model-capabilities` 插件抓取两个公开数据库、维护持久缓存，并为每个数据库选择一份目录——成功抓取的结果，否则是无论多旧的缓存，再否则是随包快照。两个数据库各自独立抓取，任一失败都保留该数据库先前的目录；刷新是插件持有并在销毁时中止的后台工作，因此启动绝不等待网络。配置是 `model-capabilities` 设置命名空间（`publicMetadata: { enabled, refresh, cacheTtl }`），其中 `enabled: false` 完全不应用任何公开目录也不发出请求，`manual` 与 `never` 都不自动抓取，`cacheTtl` 以 `7d` 这样的时长书写。来源信息新增了抓取时间与 `cache` 出处。

切片 4 加入了命令界面与随包注册。`--models-sync=check` 报告每个已配置模型的当前声明、解析出的等级、来源、命中的提供方条目、匹配方式、出处、可用的抓取时间、答案是否权威，以及同步会采取的动作；`--models-sync=write` 只持久化权威的按提供方匹配结果；`--models-explain=<route>/<model>` 打印单个模型的完整链路。`--models-refresh` 是 `manual` 允许而 `never` 拒绝的显式用户触发抓取。这些操作读取运行时自身的 store 与解析器，因此不存在第二个匹配器；写入通过设置接缝以一次校验过的 `llm-pi-ai` 合并完成，只重述它触及的路由。该层挂载在随包的 Harnessy 产品补丁层中、位于 Command Code 之后，依靠声明的服务依赖而非文件位置，因为 Loader 会并行挂载同级行，只有该依赖才能让 Command Code 自己的来源先注册。

该层为 models.dev 路由与 OpenRouter 路由给出按提供方匹配的结果；把有歧义或唯一的仅 id 匹配保留为建议且绝不自动应用；并让适配器原生与 Command Code 的答案优先于任何公开主张。网络关闭时由随包快照供给；刷新失败时陈旧缓存继续供给；畸形响应不改变任何东西。这些全部成立，而命令行会报告每个答案由其中哪一项产生。

既有已声明模型的行为与今天完全一致，Command Code 保持其现有答案，且无需任何配置迁移。检查模式下的同步不修改任何内容；写入模式下它会加入按提供方匹配的结果，绝不覆盖声明，并让设置文档的其余部分保持原样。两种模式都已实现并针对实际配置验证：检查是逐字节只读的，而对其余行都是建议或未解析的部署执行写入会让文档逐字节不变。

诊断能够针对任意提供方与模型回答：能力由哪个来源提供、匹配是否按提供方进行、命中了哪个提供方条目、数据是实时、缓存、随包还是本地，以及何时抓取。来源、匹配方式、命中的提供方条目、模型身份、权威性、出处（`fixture`／`bundled`／`live`／`cache`）与抓取时间都能由 `--models-sync`、`--models-explain` 与 Models 页面回答。

切片 5 加入了 Models 页面的展示，并完成该功能。插件如今还提供 `modelCapabilities/inspect` Remote，为每个已配置模型返回一份投影——该层是否启用、实际生效的按提供方匹配，以及不生效的仅 id 主张——由运行时接缝与命令行所用的同一套“已配置路由”联接与同一个解析器构建。`@deepseek-ai/dsh-api-remotes` 挂载它，因此 Client 只读取一份声明，且不导入任何 Host 包。每个模型行渲染其等级来自何处：用户声明的行显示**已配置**，否则显示**公开元数据**并附带数据库、匹配到的提供方条目，以及该答案是实时、缓存还是随包，时间通过共用的相对时间分档标注。随包目录不显示抓取时间；`fixture` 出处被隐去；禁用的层直接说明，而不是呈现一个禁用层同样会产生的“没有主张”。

仅凭模型 id 的匹配绝不会被显示为能力；互相矛盾的声明以“存在分歧”的形式报告，并在下方逐条列出，不选胜者。没有任何数据库提及的模型保持普通的未声明行。被声明压过的公开主张会在声明旁标注为未被应用，而本页绝不调和二者。已应用与建议之间的区别以文字承载，绝不只靠颜色；每个字符串都是 locale 所有的文案。

该功能已完成。Models 页面展示的来源信息，与运行时、`--models-sync` 和 `--models-explain` 使用的是同一条链路；随包的 Harnessy 组合让能力来源注册在 Command Code 之后；四种端到端状态——本地声明、按提供方感知的公开匹配、仅 id 建议与未解析模型——都是在该组合中被观测到的，而不是假定的。

**有意留作未来工作，而非缺口。** 周期性刷新定时器、推理强度之外的能力类型、`models sync`／`models explain` 子命令拼写，以及把公开主张与显式声明自动调和，都是本 Note 记录的扩展方向，而不是它未完成的部分。上述验收标准均不要求它们。

**实现切片 2 时记录的偏差。** 快照是生成出的 TypeScript 数据模块，而非 JSON。JSON 本是首选，但本仓库为每个包发布精确的 `files` 列表，并在 NodeNext 消费者检查下编译每个包已构建的声明，而这两者都无法承载受版本管理的 JSON 文件：`tsc` 会把该导入留在生成出的模块中而不是内联它，于是发布树只能通过一条约束门禁未建模的路径暴露数据。生成出的模块承载同样的数据，却没有这些摩擦，且包会像对待任何其它源码一样把它打包进入口。

快照还记录每份捕获的仓库输入路径与内容摘要，而非来源 URL，因为捕获是一个已抓取的文件，只有其字节能证明是哪一份；URL 属于产出下一份捕获的实时抓取。生成是从已提交的精选捕获离线完成的，而非抓取上游，因此门禁是确定性的，任何测试或门禁都不访问网络。“陈旧”的判定是内容相对捕获与当前生成器，而非时限；基于时限的刷新策略属于切片 3 的配置，如今只是挂载时的一条建议性日志，绝不让其失败。

**实现切片 3 时记录的偏差。** 设置命名空间是 `model-capabilities`，而非 `modelCapabilities.publicMetadata`：设置接缝只接受小写连字符标识符作为文档顶层键，带点的命名空间不是其中之一。段落形态未变——一个含 `enabled`、`refresh` 与 `cacheTtl` 的 `publicMetadata` 对象——因此所记录的配置就是部署写在该键下的内容。

`cacheTtl` 是带一小套语法的字符串（`500ms`、`30s`、`15m`、`12h`、`7d`），而不是仓库其它地方配置时长所用的 `…Ms` 数字：刷新节奏以天为单位陈述，而那里写原始毫秒数是危险的。仓库中没有任何其它地方解析时长，因此没有既有表示法可复用；语法被限定为正整数加一个单位，使每个被接受的值只有一种读法。

网络被禁用时随包快照仍然可用，这正是本 Note 提案所记录的：`enabled: false` 完全不应用任何公开目录——随包的、缓存的与实时的都不应用——而 `refresh: never` 与 `refresh: manual` 继续在不抓取的前提下供给缓存与快照。两个开关回答不同的问题：`enabled` 是该层是否作答，`refresh` 是它是否可以使用网络。

`manual` 与 `never` 在本切片中行为相同。它们保持区分，是因为未来的同步命令必须在 `manual` 下被允许抓取、在 `never` 下被禁止；把两者合并会让这件事变成破坏性变更。

每轮挂载与每次设置变更各运行一轮刷新，没有定时器也没有重试。失败的数据库会在下一轮重试，因此运行数周而不重启或重新配置的部署只刷新一次。周期性定时器属于随部署而变的节奏，应归于配置而非硬编码间隔。

**实现切片 4 时记录的偏差。** 命令是该应用自身命令行上的开关（`--models-sync`、`--models-explain`、`--models-refresh`），而不是子命令树，因为那正是本仓库应用已经拥有的界面：启动器只解析自己的开关，其余全部原样交给启动后的树，由应用插件声明自己的开关家族与 `--help`。两个操作都位于包内且不依赖 argv，因此本 Note 所勾画的 `models sync`／`models explain` 拼写日后可以加入，而无需改动解析或同步逻辑。

`check` 不会访问网络。`--models-refresh` 是单独的开关，因此只做报告的调用绝不会抓取；刷新策略在任何操作运行前读取：`manual` 允许显式请求，`never` 以失败拒绝它而不是悄悄报告陈旧数据，`enabled: false` 则报告该层已禁用而不是绕过策略。

随包行相对 Command Code 的优先级是一条声明的服务依赖（`inject: [commandCodeController]`），而不是补丁文件中的位置。Loader 会并行挂载同级行，因此文件位置不决定任何顺序——本切片的首次尝试把该行放在 Command Code 之后，公开来源仍然先注册；如今有一个针对真实组合的端到端测试去观测这一点，而不是假定它。

某行已声明等级集时，它旁边的已解析主张只被报告而不会被套用，且报告会打印目录自身的陈述，供人判断被保留的那份声明。调和两者是用户决定，而不是同步决定。

只有随包的 Harnessy 产品补丁层挂载该层。官方 profile 既不挂载 Command Code 也不挂载公开元数据，因此在那里加入它会把一项产品行为授予从未要求它的部署。

**实现切片 5 时记录的偏差。** 来源信息以一个新的 `modelCapabilities` Remote 命名空间跨越 Client 边界，而不是作为现有 `llm/discoverModels` 回复上的一个字段。Models 页面需要每个*已配置*模型的状态——包括仅 id 主张与禁用的层——而发现只是对草稿端点的一次性探测，来源对它要么给出能力要么什么都不给：建议永远不会跨越它。那里的一个字段无法表达本页必须区分的六种状态中的四种。

Remote 边界类型位于包的仅类型 `./types` 子路径，因为生成器要求每个边界类型都能从某个公开的非根子路径到达，也因为导入包 barrel 的 Client 程序会把它的 Host 运行时模块及其 Node 内置模块拉进浏览器程序。

该投影有意省略该行自身的声明：本页在草稿中编辑它，因此 Host 的那份副本只会在编辑与提交之间变成陈旧值，而本页渲染的是草稿所述内容。它同样省略路由的设置字段与同步判定，界面用不到它们。

`fixture` 出处渲染时不带出处行，而不是打出 `fixture` 这个词：该行仍报告其数据库、提供方与匹配方式，且没有任何构建期词汇进入已发布界面。

## 风险

随包快照会变旧：其生成日期必须在诊断中可见并受门禁约束，以免静默腐化。公开数据库是对网关的第三方主张而非保证，因此按提供方匹配必须足够严格，以免近似的主机名把一个网关的控件归属给另一个。缓存引入了第二份持久产物，其损坏必须降级到快照而不是报错。范围：来源机制是为承载更多能力而建，本次改动不得膨胀为去实现它们。
