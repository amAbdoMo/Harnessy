# @deepseek-ai/dsh-client-ui-settings-subagents

[English](README.md) | 中文

## 概述

Harnessy 的子代理页面用于配置每个角色的用途、路由、模型、推理强度、访问级别、调用策略、工具和指令。摘要卡使用紧凑 badge 和体现风险的访问颜色。编辑器归拢高级字段，可在不消耗模型用量的情况下测试解析后的设置，提示自动角色重叠，并公开委派限制。创建、复制与编辑只暂存一份本地草稿；保存执行一次完整 Host 写入，取消则丢弃草稿。新 ID 在首次保存前可编辑，校验会说明缺失的必填值。运行时诊断和工作区覆盖保留在折叠区中。该页面仅包含在 `custom-harness` 浏览器 profile 中。

<a id="use-this-package"></a>
## 使用本包

与 Host 角色目录插件一同挂载客户端行。`custom-harness` 产品补丁层已包含该客户端行；拥有 `subagent-roster` 设置分区与 `subagentRoster` Remote 命名空间的 Host 行，则由需要该角色目录的配置档挂载。

```yaml
- id: ui-settings-subagents
  name: '@deepseek-ai/dsh-client-ui-settings-subagents'
```

该页面以设置导航中的 `子代理` 条目出现。它通过共享设置作用域读取 `subagent-roster` 设置分区，并通过 Host 的 `subagentRoster` 与 `session` Remote 命名空间读取已解析的角色、路由授权、已存文档与模型目录。

### 页面管理的内容

| 区域 | 用户可做的操作 |
|---|---|
| 角色 | 添加、重命名、启用、禁用、复制与删除 **全局** 角色。创建与复制会打开禁用且可编辑的草稿，现有角色的修改会保留在本地直到点击“保存更改”，取消不会产生写入。每张折叠卡片显示用途与紧凑策略 badge；开关标签只显示当前的“已启用”或“已禁用”状态，创建操作与相邻输入框等高。编辑器把路由指引以及可选的身份、指令、工具、运行时、调度、超时与深度放入折叠区 |
| 测试角色 | 刷新所选运行时与模型目录，验证路由指引是否完整，并在不启动子代理、不消耗模型用量的情况下报告所选后端、模型、访问级别与调用策略 |
| 运行时状态 | 默认折叠安装、版本与登录诊断；能够自述的运行时会提供确切登录命令与重新检查操作 |
| 模型与推理强度 | 固定一条精确的提供方/模型路由、让角色继承调用方 Agent 的路由，或让该角色改为由 Agent 选择。选项来自该角色后端所拥有的目录。来自 Host 目录的模型只提供它公布的级别，未公布任何级别时则不提供；后端自有空间中的路由则提供该后端接受的级别，因为其清单本身不列出级别。更换模型时会清除新模型未提供的推理强度 |
| 工作区覆盖 | 默认折叠高级的按工作区角色补丁；打开后，每个字段都会显示此工作区是覆盖了它还是继承了它，并可逐字段、按整个角色或按整个工作区重置回继承状态 |
| 自动路由 | 开启由 Agent 选择模型，并授权其选择必须解析到的精确 `{ provider, model }` 路由 |
| 委派限制 | 可选择“自适应”，让父 Agent 决定最小的有效批次，也可设置更严格的手动安全上限；两种模式都受 Host 的 16 硬上限约束，并共用可编辑的默认超时 |

角色的 ID 一旦存在便固定不变，因为它既是 Agent 使用的名称，也是覆盖层打补丁所用的键；复制角色会生成新的 ID，且副本以禁用状态起始，因此同一个任务绝不会在未经审视的情况下出现第二条生效的路由。删除角色会在同一次写入中一并删除所有针对它的工作区覆盖。

完全访问会在原处标注其代价，且页面从不会把访问级别呈现为 Agent 可以放宽的东西：角色只能收窄调用方。

“测试角色”执行本地验证以及目录与运行时刷新。它不会调用模型、启动子对话，也不能保证将来的提供方请求一定成功；运行时身份验证与目录可用性是页面无需消耗用量即可验证的最早事实。

### 文案与可访问性

所有字符串都来自 `settings.subagents` 字典，该字典以英文和中文注册。输入框、文本域、按钮与共享 `Select` listbox 使用可见标签和 `aria-describedby`；不含图标的操作都带有可见文本，且每个控件都有可见的共享焦点环。在窄视口下，布局会折叠为单列。

### 设计要点

- **Host 拥有取值，页面拥有编辑。** 已存文档即设置分区；卡片由它渲染，每次编辑只写入真正改动的顶层字段，因此同一次设置往返周期内的两次编辑会组合，而不会互相覆盖。
- **编辑以计算时所用的修订号作栅栏。** 针对已结算的镜像文档所做的写入会携带该修订号，因此在别处发生变化的文档会被拒绝，而不是被静默覆盖；当页面仍在基于自身编辑组合时，则由作用域的队列承担栅栏。
- **目录是可选择路由的唯一来源，具体读取哪一个由角色的后端决定。** 路由经由 Harnessy 解析的后端使用 Host 目录，因此部署新增提供方时此处无需改动；拥有自身模型空间的后端则改用其自己的清单，因为组合出的运行时并不运行其中的模型，也就没有对应适配器。无论哪种情况，来源未公布的路由仍会列出、标记为不可用，并且可被移除，而不会从已保存的角色中消失；来源读取失败会继续显示为行内提示与失败的“测试角色”结果。
- **推理强度绝不凭空捏造。** 推理强度控件只提供路由所属目录所声明的级别。Host 目录中的模型提供它公布的级别，未公布任何级别的模型会显示说明文字而非控件，后端自有空间中的路由则提供该后端自己的级别；无论哪种情况，新选模型未提供的推理强度都会从已存路由中清除。
- **后端的级别是它自己的属性。** 每个拥有自身模型空间的后端的词表都位于 `backends.ts` 中该后端名称旁，其中包含表示“不发送任何级别”的 id——选择器把它呈现为模型默认选项，而不是一个单独的级别。新增这类后端只需多一行表项，且没有任何字面 id 进入选择器。
- **Host 解析，浏览器呈现来源。** 已解析的角色读取提供委派实际使用的取值与逐字段覆盖来源；每次写入被接受后页面都会重新读取，因此继承/覆盖状态会收敛到已提交的文档。
- **一次角色编辑就是一份完整草稿。** 字段、开关、模型选择与高级值都会保留在本地，直到用户点击保存。Client 验证会镜像 Host 中可由用户修正的身份与必填字段检查；单次带 revision fence 的写入到达后，Host 仍是最终权威。
- **按配置档门控。** 除非浏览器产物按 `custom-harness` 构建，`apply` 会提前返回。

<a id="model-experience"></a>
## 模型体验

无。该包是浏览器端设置页面，不注册任何工具、提示词分区或模型可见文本。

#### KV Cache 影响

无；该包既不组装也不发送提供方请求。它写入的角色只改变 Host 角色目录工具在下一次委派时报告的内容，而不改变任何请求的内容或顺序。

## 已知限制与后续工作

<a id="known-limitations-and-deferred-work"></a>

- **工作区覆盖编辑器显示已存储的覆盖，而非工作区选择器** —— 页面为会话自身的工作区解析覆盖；没有工作区的会话只提供全局角色。
- **工作区无法从本页面移除角色** —— 覆盖层的 `removed` 列表会被读取并清理，但此处没有对应控件，因此暂时还无法从浏览器中为单个工作区移除角色。
- **覆盖编辑器的模型行无法把推理强度与模型分开设置** —— 该行写入整个模型策略，因此工作区要么同时固定路由与推理强度，要么两者都继承。
- **后端自有的级别来自该后端，而非其清单** —— Command Code 自带的目录只包含 id 与描述，别无其他，因此其路由提供的级别是本页面为该后端记录的级别；未记录级别的后端不提供任何级别，而已保存路由上已有的级别无论如何都会保留。
- **Plugins 中的子代理卡片在 Harnessy 之外仍可用** —— `custom-harness` 构建会省略这张重复卡片，因为完整角色与路由流程已位于子代理页面；其他 profile 仍保留较旧的 `subagent-model-selection` 界面。
- **没有角色排序** —— 角色保持存储顺序；页面把新角色追加到末尾。

<a id="dev-note"></a>
### 开发备注

<details>
<summary>面向维护者的工作上下文——点击展开</summary>

- **本页面写入的每一项策略都由 Host 强制执行** —— 页面只写入字段；访问级别收窄、调用方式与路由授权均由角色目录插件解析并强制执行，因此此处的缺陷无法放宽子进程。
- **选择器有意留在本包内** —— `ui-model-selection` 中的 `ModelSelect` 会把选择提交给实时会话，而不是发出受控取值，且一个插件不得导入另一个插件的组件，因此本页面在共享目录数据之上自带控件。

</details>

**Runtime invariant:** 不发布伴随文件。设置文档由设置服务拥有，已解析的角色目录、路由授权与运行上限由 Host 角色目录插件的 Remote 命名空间拥有。
