# Companion 中继父任务集成

本次仅交接源码，不启用配置档案、不部署中继、不安装依赖，也不提供 Android UI。父任务负责在三个获准包目录之外完成以下修改。

## 仓库接线

- 在 [profile.ts](../../boot/app-boot/src/profile.ts) 中增加 `PROFILE_TEMPLATES['companion-relay'] = { bundles: ['@deepseek-ai/dsh-companion-relay-bundle'] }`；不要使用未知配置档案的回退路径，因为它继承 `dsh-base`。
- 将 bundle 加入 [CLI 清单](../../../apps/cli/package.json) 的启动器解析依赖，并通过父任务负责的正常依赖流程协调锁文件。这里要求的所有第三方版本已存在于工作区；本次交接不执行安装。
- 在 Host 汇总配置中注册三个包项目，将包名源码路径加入基础解析映射，并在依赖检查器中分类运行时和开发导入。包内配置声明其直接工作区引用。根 tsdown Host 阶段发现包清单，并打包已输出的 `index`/`startup` 入口；无需新增原始 Node 应用、可执行程序或独立 Web 服务入口。
- 增加 README Model Experience `none` 分类、文档所有权与预算记录、双语配对记录，以及仓库要求的配置和模块生成文档。协议细节由 [协议包](../../util/companion-protocol/README.md) 所有，而不由根目录目录表所有。
- 在解析器和锁文件集成后增加配置档案级 CLI 与发布产物验收检查。包回归仅有源码，未运行。在模板、产物、部署来源和预算数据就绪前，不得声称已支持启动。

## PC 与 Android 消费者

- 单独实现 PC 连接器：持久身份与授权/邀请存储、原子一次性邀请消费、显式用户授权、撤销、经批准的 Session 投影、有界收件箱接纳，以及每个 Harness home 的本地单所有者锁。中继的单 PC 所有者检查不能替代本地锁。
- 单独实现原生 Android APK 源码，使用兼容 Java 的 P-256 SPKI/DER、HKDF-SHA256 和 AES-GCM。PC 身份固定、手机私钥保管、部署来源验证、重连所有权和纯文本渲染均保持原生实现；不得替换成 PWA。
- 应用分派前验证对端角色、身份、路由、socket 实例代次、通道 ID、授权/代次、请求关联、计数器及双方加密确认。每次重连生成新 nonce 和临时密钥，放弃旧订阅，并将确认丢失的变更显示为送达未知。不得自动重试 `submitText`。
- PC 连接器必须在进程总限制之外执行显式应用预算中的每授权保留量和时间字段；协议解析器仅执行线路字节、字段数量和字段有效性限制。没有回执查询或持久提交账本。

## 部署与验收所有权

部署操作员提供真实规范 HTTPS 来源及同主机托管 TLS 反向代理，保留公开 Host，阻断对上游的直接访问，并在 Node 上游之前执行 TLS、HTTP、升级、连接和流量限制。中继有意忽略转发 IP 请求头；因此同主机代理的所有客户端共享一个传输 IP 预算。改变此策略需要显式配置的受信代理实现，而不是盲目信任转发请求头。

启用前，父任务运行聚焦的无输出类型检查、协议和中继行为回归、Loader 组合及释放、双语/文档检查、依赖/包卫生检查、已发布 Node 导入检查，以及 Node 与 Android 互操作验证。手动验证格式错误/重放证明、错误 Host/路径/角色、未知 PC、重复 PC 所有者、目标替换竞态、分片/队列/速率/时间限制、慢读者、撤销和确认丢失。本交接不将任何测试、检查、构建、浏览器/服务器/提供方调用、云部署、凭据访问、提交或推送描述为已执行。
