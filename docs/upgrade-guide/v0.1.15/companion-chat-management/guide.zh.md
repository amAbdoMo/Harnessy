# 伴随应用聊天管理权限与兼容性

[English](guide.md) | 中文

## 变更

已配对的 Android 手机保留读取会话和提交文本的现有权限；仅配对不会授予聊天管理权限。Desktop Main 的原生 **已配对手机 → 启用聊天管理** 要求单独确认指纹；默认选项为 **取消**。此权限不允许控制模型、账户、工具批准或凭据。

仅支持四种操作：在真实 Workspace 中创建空聊天、重命名、归档和置顶/取消置顶。永久删除已推迟；没有“删除”按钮，归档会保留历史。归档拒绝忙碌聊天，不提供便捷“停止”操作。新聊天使用电脑默认预设，不接受任意提供方设置，且在用户发送消息前不提交文本、不调用模型或工具。

新手机 API 要求先更新匹配的电脑端：受权限控制的 Workspace 目录包含已注册的空 Workspace，不暴露路径，并通过四条专用命令执行上述操作。普通导航仍仅列出含有返回 Session 的分组。新增的 `SessionCreateRequest.newSessionId` 要求严格全新身份，与旧字段 `sessionId` 互斥；旧收养行为不变。参见[创建语义](../../../../packages/api/session-controller/README.zh.md#use-this-package)。

电脑授权字段 `sessionManagementV1?: true` 缺省时拒绝管理权限。有效的 v1 身份记录可直接加载，启动时不重写。下一次合法授权写入将存储 v2，除请求的授权变更外，保留身份密钥、现有授权和代次。旧版 Host 拒绝 v2。

Android `OperationStore` v2 读取 v1 时不修改存储，合法写入保留不确定性标记、修复标记和配对密钥。可能写入前先提交阻止记录；结果未知时绝不重放。`managed` 的 applied 要求 PC 所有者提交和创建／重命名刷盘完成；部分生效或刷盘失败表示未知，不表示回滚、收件箱接纳或持久重放回执。参见[完成语义](../../../../packages/host/companion-host/INTEGRATION.md#actual-relay-and-endpoint-wire)。

## 迁移

1. 先在 Harnessy 中通过**检查更新**更新电脑端，再更新手机。仅修改源代码不会更新正在运行的应用。请遵循[Android 验证要求](../../../../apps/android/README.zh.md#limits-and-verification)。
2. 在原生 **已配对手机** 中，为目标手机选择 **启用聊天管理**，比较完整指纹并确认。不要重置身份或重新配对。
3. 原位安装匹配的 Android 应用。保留应用数据、配对密钥、不确定性标记和修复标记；绝不要卸载或清除存储。
4. 验证真实 Workspace（包括已注册的空文件夹）。使用 **新聊天**；确认电脑上存在空聊天，并检查每项操作的状态/结果，包括归档保留历史，以及忙碌时拒绝归档且不停止任务。
5. 结果未知或回复丢失时，先在电脑上检查目标，再明确审查不确定状态或尝试新的操作意图。绝不要自动重试或重发。

回滚时，旧版 Host 无法读取授权写入后的 v2。请安装匹配的新版 Host，不要删除密钥。不要手动编辑记录、重置身份或期待自动降级。
